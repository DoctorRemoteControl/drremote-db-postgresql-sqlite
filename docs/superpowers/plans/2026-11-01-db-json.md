# Optional DB JSON Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add optional JSON result mapping and JSON parameters to all supported databases through existing transaction connections.

**Architecture:** One JDBC/Jackson adapter bundle and an independent Karaf feature. Existing core APIs and dependency sets remain stable.

**Tech Stack:** Java 17+, Maven, Jackson 2.22.4 (annotations 2.22), JDBC, JUnit 5, Karaf 4.4.11.

**Spec:** `docs/superpowers/specs/2026-11-01-db-json-design.md`

## Global Constraints

- English; Java 17+; public development version `1.1.0-SNAPSHOT`; Apache-2.0.
- Optional artifacts `de.drremote.db:json` and `json-features`; API package `de.drremote.db.json.api`.
- No Jackson dependencies/imports in existing database cores and no changes to private source/origin.
- Caller retains the connection and transaction; no implicit commit, rollback, close, or connection-setting changes.
- JSON query/binding support is this increment; document-store APIs are excluded.

## Review Focus

- Ambiguous row shapes: duplicate/blank labels and missing explicitly declared JSON columns fail clearly.
- Data fidelity: big integers/decimals, JSON null versus SQL NULL, and ordinary JSON-looking text keep their intended meaning.
- Driver differences: PostgreSQL JSON/JSONB and DuckDB JSON are parsed by metadata; SQLite TEXT is explicit.
- Resource failures: binding, execution, and mapping errors close statements/results without closing the caller's connection.
- Optional OSGi use: installing a database alone needs no Jackson; installing JSON resolves all required Jackson packages.
